# 架构决策记录（ADR）

本目录记录 OpenWork 的架构决策。每条 ADR 说明**在什么背景下、做过什么选择、为什么、代价是什么**，供后来者（包括 AI agent）在不重新推导的前提下做出与既有设计一致的决定。

---

## 规则

1. **一条 ADR 一个决策。** 不写"架构总览"，总览放在 `docs/architecture/`。
2. **不删除、不改写结论。** 决策被推翻时，新增一条 ADR 并在新旧两条上加 `Supersedes` / `Superseded by` 链接。历史本身是信息。
3. **状态明确：**

| 状态 | 含义 |
|---|---|
| `Proposed` | 待定，已按此方案实现（长任务执行期间自决的技术选择用此状态） |
| `Accepted` | 已采纳，必须遵守 |
| `Deprecated` | 不再推荐，但存量代码可能存在 |
| `Superseded by NNNN` | 已被新决策取代 |

4. **必须写代价。** 没有"只有好处"的决策。明确写出放弃的选项与接受的限制。
5. **落地可检验。** 至少写一条"如何检查是否被遵守"（静态检查、测试、审查项）。

## 文件命名

```text
docs/adr/
├── README.md
├── template.md
├── 0001-modular-monolith.md
├── 0002-tenant-isolation.md
└── proposed/
    └── 0042-xxx.md
```

`Accepted` / `Superseded` 放在根目录；未决决策放 `proposed/`，转正后移动到根目录并更新状态。

编号四位递增，永不复用。
