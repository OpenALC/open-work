## 一、版本号

格式：`0.MINOR.PATCH`

**第一段固定为 `0`，日常发版不递增。** 只有发生与旧版本完全无法衔接的根本性重构时才考虑动它，届时应另起版本线单独讨论。

| 变更 | 递增 | 示例 |
|---|---|---|
| 破坏性变更：删改已发布 API、不兼容数据库变更、需要人工介入的升级步骤；里程碑级收口 | MINOR（第二段）+1，PATCH 归零 | `0.4.7` → `0.5.0` |
| **其余一切**：新功能、新端点、新模块、行为变更、修 bug、性能、文档、安全补丁 | PATCH（第三段）+1 | `0.5.0` → `0.5.1` |

也就是说：**日常绝大多数发版只动第三段**，第二段一年动几次就够了。功能实现和缺陷修复都由第三段承担。

两段都按十进制递增，不设上限：`0.5.9` → `0.5.10`，`0.9.0` → `0.10.0`，`0.99.0` → `0.100.0`。不要进位成 `1.0.0`。

### 代价与缓解

版本号不再区分「纯修复补丁」和「含新功能的补丁」。私有化部署需要判断「这次能不能直接升」时，看 CHANGELOG 而不是版本号：

1. 纯修复版本在 `CHANGELOG.md` 标题后标注 `(仅修复)`
2. GitHub Release Notes 从 CHANGELOG 生成，天然带这个标注
3. 升级风险看 `Changed` 与 `Security` 两节——有内容就要认真读

预发布后缀：`-alpha.N` / `-beta.N` / `-rc.N`，不设上限（`0.10.0-rc.12`）。

产品版本、API 版本（`/api/v1`）、Connector SDK 协议版本、数据库迁移版本**各自独立**，不互相绑定。API 路径里的 `v1` 与此处的产品版本不是一回事，不受首段固定为 0 的影响。

### Git 标签

`v0.MINOR.PATCH`，例如 `v0.10.3`。

`release.yml` 的触发规则用 glob 语法（**不是正则**，"+" 会被当作字面字符）：

```yaml
tags:
  - 'v[0-9]*.[0-9]*.[0-9]*'
  - 'v[0-9]*.[0-9]*.[0-9]*-*'
```

`[0-9]` 匹配一位数字、`*` 匹配任意字符，因此任意位数都能触发：`v0.9.0`、`v0.10.0`、`v0.100.12`、`v0.10.0-rc.3` 均可。

## 二、发一版

```bash
git switch main && git pull --ff-only
git switch -c chore/release-v0.10.0
```

1. `CHANGELOG.md`：把 `Unreleased` 改成 `## [0.10.0] - YYYY-MM-DD`
2. `docs/api/openapi.yaml` 的 `info.version` 同步
3. 提交 `chore(release): v0.10.0`，合入 `main`

然后打标签：

```bash
git switch main && git pull --ff-only
git tag -s v0.10.0 -m "v0.10.0"
git push origin v0.10.0
```

`release.yml` 自动跑，不需要手动传制品。

## 三、发之前看一遍

- [ ] `main` 的 CI 绿
- [ ] `CHANGELOG.md` 有本版本段落，条目和提交类型对得上
- [ ] OpenAPI 相对上一版没有非预期破坏性变更（有的话在 Breaking Changes 里写明）
- [ ] 迁移在空库能跑通
- [ ] 从上一版升级演练过一遍
- [ ] `govulncheck` / `pnpm audit` 没有 high 以上
- [ ] 上一版能用的客户端连新服务端没问题

## 四、数据库变更

用 expand / contract，让新旧版本能同时跑：

| 阶段 | 做什么 |
|---|---|
| 本次发布 | 加列加表、双写、回填 |
| 下次发布 | 读路径切到新结构 |
| 再下次 | 删旧列 |

规矩：

- 一次发布不删上一版还在用的列或表
- 大表加索引用 online DDL，回填分批
- 迁移只能从 `openwork-server migrate` 执行，不在启动时隐式执行
- 已合并的迁移文件不再修改

## 五、出问题怎么退

| 情况 | 做法 | 时间 |
|---|---|---|
| 应用 bug，数据没问题 | 镜像 tag 退回上一版 | 10 分钟内 |
| 迁移有问题 | 执行 down 迁移；不可逆的走备份恢复 | 1 小时内 |
| 客户端有问题 | 服务端兼容旧客户端，或用开关降级 | 30 分钟内 |
| 安全漏洞 | 见第六节 | 立即 |

触发回滚：错误率超 5% 持续 5 分钟、核心功能不可用、数据不一致、越权。

回滚完写一份复盘，放 `docs/postmortems/YYYY-MM-DD-<slug>.md`。

## 六、安全补丁

1. 修复合入 `main`，打 patch tag
2. 立即推送镜像
3. 发 GitHub Security Advisory：受影响版本、修复版本、缓解措施
4. 严重问题目标 24 小时出修复版

## 八、兼容承诺

| 对象 | 承诺 |
|---|---|
| 开放 API `v1` | GA 后至少支持 12 个月，弃用提前 6 个月公告 |
| 客户端 ↔ 服务端 | 客户端至少兼容前 2 个 minor 的服务端 |
| Connector SDK | major 内字段只增不删 |
| 配置项 | 删之前先保留并打警告日志，至少跨一个 MINOR 再删 |
