# 里程碑与长任务

> 关联：[CI](ci.md) · [发版](release.md) · [审查](review.md)

---

## 一、任务层级

| 层级 | 规模 | 交付 |
|---|---|---|
| 里程碑 M | 一个可演示的能力集合 | 打标签 `milestone/mN` |
| 长任务 LT | 1–3 天，~1–3k 行变更 | 一个分支、一个 PR |
| 小任务 ST | 30–90 分钟 | 一次提交 |

**LT 是工作单元。** 拿到一个 LT 就一路做到 DoD 全过，中途不停下来问。

## 二、长任务内不设阻塞点

这是给 LLM 连续工作的核心规则：

1. **不在执行期选型。** 技术栈在 `AGENTS.md` 里已经定死，执行时只实现不决策。
2. **遇到没定的问题自己定。** 按"最小改动 + 跟现有代码一致 + 不加新依赖"决定，在 PR 描述里写一句"自决：xxx，因为 yyy"，然后继续。
3. **缺东西就降级。** 没有 API key、没有真机、第三方服务不通 → 写内存实现或 mock，接口留着，标 `TODO(adapter: xxx)`。
4. **CI 红了自己修。** 修不好连续三次，记进 PR 的"遗留"一节，继续做后面的 ST，别停。
5. **测试必须有。** 没有测试的功能不算做完；集成测试用 CI 里的真 MySQL + Redis。

只有这四件事要停下来记一笔（仍然不停手，按最保守的方案做）：删数据/不可逆迁移、改许可证、删已发布的 API、碰密钥。

## 三、完成定义

一个 LT 做完的定义：

- [ ] `make ci` 通过
- [ ] 新逻辑有测试，关键路径有真库集成测试
- [ ] 有迁移：加了 migration，`up → down → up` 能重复跑
- [ ] 有 API：`docs/api/openapi.yaml` 已更新
- [ ] 有权限：服务端校验了，权限码登记了
- [ ] 所有查询带 `tenant_id`
- [ ] PR 描述写了：做了什么、怎么验证的、有什么风险、自决了什么

## 四、里程碑

### M0 工程基线

让它从零能跑起来，CI 能守住。

| LT | 内容 |
|---|---|
| L0.1 三进程骨架 | `cmd/{server,realtime,worker}`、`internal/` 模块目录、配置加载、slog、统一错误码与响应、`/healthz` `/readyz`、`go.mod`、`Makefile`、dev compose、Web 与 Flutter 空工程 |
| L0.2 数据层 | 迁移体系、连接池、sqlc 管线、事务帮助器、租户作用域静态检查、seed 数据 |
| L0.3 Outbox | `outbox_events` 表、同事务写入、派发器（租约 + 幂等 + 退避 + 死信）、Worker 任务注册表 |
| L0.4 认证中间件 | JWT + Redis 会话、刷新令牌轮换、租户解析、幂等键、限流、审计日志表、日志脱敏 |

**出口：** 克隆后 `make dev-up` 能起服务，`/readyz` 返回 200，`make ci` 全绿。

## 五、并行

- 后端先走，Web 按 OpenAPI 生成的客户端对接，Flutter 到 M5 再动。
- 同时最多 2 个 LT，且不要落在同一个 `internal/<module>` 里。
- LT 之间有硬依赖就后做；软依赖就先写接口和 mock。

## 六、拆 LT 的判断

一个 LT 拆不动的时候才拆。超过 3k 行、或者需要跨 4 个以上模块，就拆成 `LT.n.1` / `LT.n.2`，在里程碑表里加一行。
