# OpenWork 审查流程

> 关联文档：[里程碑规划](./roadmap.md) · [CI 流程](./ci.md) · [发版流程](./release.md)
>
> 审查模型：以 LLM 自主批量实施为主，人工审查集中在里程碑出口与发版前。

---

## 一、审查分层

| 层级 | 时机 | 审查者 | 关注点 | 时限 |
|---|---|---|---|---|
| L1 自我审查 | LT 完成前 | 实施者（LLM） | DoD 自查、差异自查 | LT 内 |
| L2 自动审查 | PR 打开时 | CI + 机器人 | 门禁、契约、租户隔离、安全 | ≤ 15 min |
| L3 交叉审查 | PR 打开时 | 独立审查 agent | 正确性、可维护性、需求一致性 | ≤ 30 min |
| L4 人工抽检 | 每日 | 维护者 | 高风险变更、抽样 | 每日 30 min |
| L5 里程碑审查 | 里程碑出口 | 维护者 | 架构、安全、文档、积压技术债 | 半天 |
| L6 发布审查 | 发版前 | 发布负责人 + 维护者 | 兼容性、迁移、回滚、制品 | 见 release.md |

原则：**机器能判定的全部交给机器**。人工只判断机器判不了的事：需求是否理解正确、抽象是否合理、风险是否可接受。

---

## 二、L1 自我审查（实施者自查）

LT 提交前，实施者必须自问并在 PR 描述中给出答案：

1. **需求对照**：逐条对照 LT 任务卡的"交付物"与"验收"，说明每条如何被验证。
2. **范围控制**：是否有超出任务卡的改动？有则拆出去。
3. **不做清单**：任务卡的"不做"是否被遵守。
4. **测试真实性**：断言是否为真实行为验证？有无被放宽、被跳过、被 mock 掉的关键路径？
5. **错误处理**：所有错误是否被处理或显式忽略并说明原因？
6. **租户隔离**：每个新增查询是否带租户作用域？跨租户路径是否有测试？
7. **权限**：每个新增端点是否声明权限码并在服务端校验？越权测试是否存在？
8. **可逆性**：迁移、配置、API 变更是否可回滚？
9. **遗留**：新引入的 `TODO` / `FIXME` 是否已登记到 `known-issues.md`？

## 三、L2 自动审查

### 3.1 门禁

以 [ci.md](./ci.md) 的分支保护检查列表为准，全部必须通过。任何一项失败不允许合并。

### 3.2 PR 机器人检查

| 机器人检查 | 阻断 | 说明 |
|---|---|---|
| `pr-size` | 否 | > 1500 行打 `size/large`，> 3000 行要求拆分 |
| `scope-check` | 否 | 跨 > 3 个模块提示拆分 |
| `doc-sync` | 是 | 改动 `internal/<module>/` 但未更新该模块 `README.md` |
| `changelog-check` | 是 | 用户可见变更未在 `CHANGELOG.md` 的 `Unreleased` 登记 |
| `api-changelog` | 是 | 改动 OpenAPI 但无对应 CHANGELOG 条目 |
| `migration-immutable` | 是 | 修改了已合并的迁移文件 |
| `permission-registry` | 是 | 代码中出现新权限码字符串但未登记到权限目录 |
| `todo-format` | 是 | `TODO` 缺少负责人或 issue 引用 |
| `no-debug-artifacts` | 是 | 提交包含 `fmt.Println`、`console.log`、`print(` 调试残留（白名单除外） |
| `generated-files` | 是 | 生成文件被手动修改（sqlc、openapi 客户端） |

### 3.3 差异扫描的安全规则

自动扫描 PR diff，命中即阻断并附修复建议：

- 未参数化 SQL 拼接
- `SELECT * FROM` 跨租户表且无 `tenant_id` 条件
- `context.Background()` 出现在请求路径
- 关闭 TLS 校验、`InsecureSkipVerify: true`
- 硬编码凭据、内部地址、测试令牌
- `os.Exec` 与用户输入拼接
- WebView 侧 `postMessage` 未校验来源
- 敏感字段明文落日志（手机号、邮箱、身份证、令牌、密码）
- 新增依赖进入许可证黑名单

## 四、L3 交叉审查（独立审查 agent）

PR 门禁通过后，由**不共享实施上下文**的审查 agent 执行，避免"自己给自己找理由"。

### 4.1 输入

- PR diff（完整）
- LT 任务卡（目标、交付物、验收、不做）
- 相关 ADR 与模块文档
- 变更涉及的 OpenAPI 片段

### 4.2 审查维度

| 维度 | 检查内容 |
|---|---|
| 需求一致性 | 实现是否覆盖任务卡全部交付物？有无多余实现？验收条件是否真的成立？ |
| 正确性 | 边界条件、并发、事务边界、错误路径、幂等、时序 |
| 数据一致性 | 事务范围、Outbox 使用、重试是否幂等、崩溃恢复 |
| 多租户 | 租户作用域完整性、跨租户越权、缓存键是否含租户 |
| 权限 | 服务端强校验、数据范围是否参与过滤、客户端判断未被当作授权 |
| 可维护性 | 分层是否被破坏、是否引入无意义抽象、命名与既有模式一致性 |
| 性能 | N+1 查询、缺索引、无界列表、同步阻塞外部调用 |
| 测试质量 | 测试是否真实验证行为、是否覆盖失败路径、是否存在伪测试 |
| 文档 | 模块文档、OpenAPI、CHANGELOG、ADR |

### 4.3 输出格式

审查 agent 只能输出三类结论，每条必须给 `file:line`：

```markdown
## 阻断项（必须修复才能合并）
- [ ] <file>:<line> — 问题描述 / 为什么是问题 / 建议修法

## 建议项（可合并，记录为后续 LT）
- <file>:<line> — 问题描述 / 建议

## 已核对（无问题）
- 租户隔离：<简述核对方式>
- 权限校验：<简述核对方式>
- 迁移可逆性：<简述>
```

要求：

- 阻断项必须有可复现的失败场景（输入 → 错误结果），不接受"风格偏好"
- 不接受"这里可能有风险"这类无具体场景的判断
- 已验证为误报的阻断项，由人工裁决并记录到 PR

### 4.4 争议处理

- 实施者与审查者意见不一致时，以 ADR 为准；ADR 未覆盖则实施者按"最小可逆"执行，把分歧写入 PR 的"需人工决策"章节
- 不因分歧阻塞 LT 完成；分歧进入 L4 人工抽检处理

## 五、L4 人工抽检（每日）

维护者每日 30 分钟，按抽样规则复核：

### 5.1 必查（每次）

- 命中 `size/large` 或跨模块的 PR
- 涉及迁移、权限、认证、凭据、WebView Bridge 的 PR
- 涉及删除代码的 PR（> 200 行删除）

### 5.2 抽样（随机）

按周随机抽取当周合并 PR 的 10%（至少 2 个），重点看：

- 测试是否被弱化
- 是否有跨租户访问
- 是否偷偷扩大了范围

### 5.3 抽检不合格的处理

| 问题类型 | 处理 |
|---|---|
| 漏掉阻断级缺陷 | 开 issue 走正常修复 LT；在 `known-issues.md` 记录 |
| 测试被弱化 | 立即修复测试；在 AGENTS.md 增加对应规则 |
| 同类问题重复出现 ≥ 2 次 | 转化为自动化检查项，进入 CI |
| 需求理解偏差 | 修正任务卡模板或补充 ADR |

## 六、L5 里程碑审查

里程碑出口执行，产出 `docs/development/reviews/m<N>-review.md`：

1. **演示验证**：按预置脚本从零跑一遍本里程碑的能力
2. **架构复核**：与 `roadmap.md` 的模块边界对照，是否出现越界依赖
3. **安全复核**：越权矩阵、租户隔离 fuzz、密钥扫描、依赖漏洞
4. **契约复核**：OpenAPI 与实际行为一致性，破坏性变更累计情况
5. **技术债盘点**：`known-issues.md` 逐条评估：修复 / 接受 / 转化为 LT
6. **下一里程碑调整**：根据实际速率修订 LT 数量与粒度
7. **结论**：通过 / 有条件通过（列出必须在下个里程碑前处理的项） / 不通过

## 七、L6 发布审查

见 [release.md](./release.md) §四 的检查清单，由发布负责人组织，逐项留痕。

---

## 八、始终不允许的操作

无论审查结论如何，以下操作在所有 LT 中禁止：

- 为了让 CI 通过而删除或跳过测试、降低断言、加 `t.Skip`
- 使用 `--no-verify` 绕过 commit hook
- 使用 `//nolint` / `eslint-disable` 屏蔽问题而不在同一 PR 修复或说明
- 直接 push 到 `main`
- 修改已合并的迁移文件
- 手改生成代码（sqlc 输出、OpenAPI 客户端）
- 在 PR 中夹带与本 LT 无关的重构
- 将密钥、令牌、生产地址提交到仓库
- 在日志中输出敏感字段原文

## 九、审查效率指标

每月统计，用于调整流程而非考核个人：

| 指标 | 目标 |
|---|---|
| PR 首次门禁通过率 | ≥ 80% |
| L3 阻断项中真实缺陷占比 | ≥ 70%（低于则说明审查噪声大） |
| 漏检率（L4/L5 发现的阻断级缺陷 / 已合并 PR） | ≤ 5% |
| PR 从打开到合并的中位时长 | ≤ 4 小时 |
| CI 失败中基础设施原因占比 | ≤ 10% |
| 技术债存量（`known-issues.md` 未关闭项） | 不随里程碑增长 |
